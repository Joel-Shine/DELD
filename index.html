INTRODUCTION

The project involves the design and implementation of a custom 4-bit digital logic calculator capable of executing core operations entirely through fundamental logic gates and integrated circuits.

This calculator acts as a practical demonstration of hardware architecture, bridging the gap between theoretical logic and physical hardware design without relying on software-based microcontrollers.

PROBLEM STATEMENT

System Challenge

Modern computing abstracts operations via software. However, designing a multi-operation ALU from scratch requires solving physical complexity challenges—such as precise multiplexer routing, finite state control, and strictly minimizing propagation delay across discrete physical ICs.

Project Goals

  • Arithmetic Execution: Implement core 4-bit operations including Addition, Subtraction, Multiplication, and Division using combinational logic.
  • Logical Operations: Integrate foundational bitwise functions including AND, OR, and XOR logic.
  • Hardware Portability: Develop corresponding Verilog code for the hardware to enable simulation and future FPGA expansion.

CIRCUIT DIAGRAM

SYSTEM STAGE BREAKDOWN Architecture Overview

Input & Registers
4-bit operand entry routing (A3..A0, B3..B0) feeds directly into 4-bit Register A and Register B for stabilization prior to computation.
Combinational ALU
Handles immediate logic execution, housing the Adder/Subtractor (using 2's-complement logic) and the bitwise Logic Unit (AND, OR, XOR).
Sequential Unit
Multi-cycle computational block driving the Multiplier (shift-and-add) and Divider (repeated subtraction) via an FSM-driven accumulator, counter, and comparator.
Control FSM (Moore/Mealy)
Orchestrates system states sequencing: operand entry → op-select → compute (single/multi-cycle) → store/display.
Memory Unit
Integrated 8x4 RAM block managed by a 3-bit address line (ADDR) for dynamic operation result storing and recall.
Output & Display Path
The operation-select controlled Output MUX routes the final 4-bit signal to a BCD to 7-segment Decoder, driving the final numerical display.

INDIVIDUAL CIRCUIT COMPONENTS Simulation Phase

Adder
74283 4-bit full adders with 7486 XOR inversion for 2's-complement subtraction.
Logic Control Block
74139 decoder and 7474 flip-flops enable the selected unit and sequence each operation.
Operand Assembler
Latches the DIP-switch inputs into 74173 registers to form stable 4-bit operands A and B.
Priority Encoder
Two cascaded 74148s convert the 13 key lines into a single binary op-code.
Div/Mul Counter
74191 counters with a 7485 comparator track the repeated add/subtract cycles on each clock.
Keypad Matrix
13 push buttons with 10 kΩ resistor networks, debounced through 7414 Schmitt triggers.

RESULTS AND INFERENCES Simulation Phase

Fig 1 — Sequential Arithmetic (3 × 4 = 12)

Operands A = 0011 (3) and B = 0100 (4) were entered, and the MUL key started the shift-and-add sequence. On every tick of the 555 clock, the circuit checked one bit of B, added the shifted copy of A to the running total whenever that bit was 1, and stepped the counter forward. After 4 clock cycles the counter stopped the operation, and the result 1100 appeared on the 7-segment displays as 12. This confirms that the sequential unit, counter and control logic work together correctly across multiple clock cycles.

Fig 2 — Bitwise Logic (5 XOR 3 = 6)

Operands A = 0101 (5) and B = 0011 (3) were entered and the XOR key was pressed. The 7486 XOR gates compared the two numbers bit by bit, giving a 1 only where the bits differ: 0101 ⊕ 0011 = 0110. The output MUX routed this to the display, which showed 6 straight away, with no waiting on the clock. This confirms that the logic unit gives an instant combinational result and that the operation-select path picks the correct unit.

DESIGN Hardware Specifications

Logic Family & Supply
One chip family · 5 V
Every chip on the board comes from the same family, so they all understand the same HIGH and LOW signals. One common 5 V supply powers all of them, and these chips are cheap and easy to find in local shops.
System Clock
≈ 10 ticks per second
The 555 timer is the calculator's heartbeat. It ticks about 10 times a second, which is slow enough for us to watch multiplication and division happen step by step. The 1 kΩ, 6.8 kΩ and 10 µF parts were picked to set exactly that speed.
Input Conditioning
Clean, single button presses
A real button doesn't press cleanly. It flickers on and off for a split second, and a chip could read that as several presses. Special smoothing chips turn the flicker into one clean press, and resistors make sure an "off" switch always reads as a firm off.
Display Drive
330 Ω on every segment
Each segment of the display is a tiny LED, and LEDs burn out if too much current flows through them. A resistor on every segment keeps them bright enough to read from the back of the class, without straining the display or the chip driving it.
Reset & Decoupling
Clean start · steady power
When power is switched on, the reset circuit holds everything still for a moment, so the calculator always starts from a clean slate. A small capacitor beside every chip works like a mini power reserve, so one chip switching doesn't disturb its neighbours.
Power Budget
Under 1 A total · 1 A+ supply
Adding up what all 60 chips and the display use comes to well under one amp. Using a 5 V supply that can deliver at least 1 A leaves plenty of headroom, so the voltage stays steady even when every segment is lit.

VERILOG PHASE

VERILOG SYNTHESIS Module Architecture

Top-Level & I/O
The calculator_4bit_top.v module wires the system. The 6x4 matrix keypad is scanned and debounced by keypad_scanner.v, and raw signals are translated via key_decoder.v.
FSM Core
calculator_core.v drives the sequencing through standard states: S_ENTER_A, S_ENTER_B, and S_RESULT, handling digit accumulation and operator latching.
Combinational ALU
alu.v handles the immediate arithmetic (Add, Sub, Mul, Div, Mod), bitwise logic (AND, OR, XOR), and comparisons across double-width output.

alu.vExecution & Error Handling
always @(*) begin
    div_by_zero = 1'b0;
    case (op_code)
        OP_ADD: result = a + b;
        OP_DIV: if (b == 0) begin
                    result = 0;
                    div_by_zero = 1'b1;
                end else
                    result = a / b;
    endcase
end

DESIGN SPECIFICATION Justification

Gate-Level Approach
Why Discrete ICs?
Avoided microcontrollers to demonstrate raw digital logic manipulation, finite state machines, and physical propagation delay management.
4-Bit Constraints
Word Size Optimization
Balances architectural complexity and physical footprint. 4-bit allows for full proof-of-concept without breadboard overcrowding and immense wiring chaos.
Power Efficiency
CMOS & TTL Logic
Selected optimal IC logic families where applicable to reduce thermal output, minimize current draw, and ensure stable logic thresholds.

HARDWARE ANALYSIS Performance Metrics

Propagation Delay

Cumulative gate delays (t_pd) across cascaded adders and extensive MUX stages were actively measured and mitigated using lookahead logic strategies.

Signal Integrity

  • Debouncing: Hardware RC filters and Schmitt triggers applied to raw keypad inputs.
  • Power Rails: Capacitive decoupling (0.1µF) implemented across all IC VCC pins to stabilize switching noise.
Clock Stability
99.8%
Measured Validation via Oscilloscope
